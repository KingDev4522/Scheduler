## 2. Non-negotiable guardrails (from PS + phase docs)

- **STOP** if asked to hardcode, hand-edit or fabricate schedules, exam results, booking decisions or validator outputs. All outputs must be generated by the application.
- Never invent field names, enum values, penalty weights or export keys — copy from the official source and cite it. If the source is absent, mark `VERIFY` and ask.
- The LLM (or agent) **never** decides schedule/booking validity; every proposal passes deterministic validation first.
- No self-approval, ever (`requester != approver`), enforced in code paths, not just hidden in UI.
- Hide inaccessible nav items **and** enforce them at the route/service level (already the pattern in `src/App.tsx`).
- Keep `npm run build` green after every change; never commit broken TypeScript.
- No secrets in git. Credentials demo-only, documented in README.
- Do not push to `main` without the user's explicit go — commit locally, then ask.
- Do not modify or "improve" organizer/validator files when they arrive.
- When blocked > 2 reasonable attempts, stop and report instead of thrashing.

## 4. Working protocol (per task)

1. **Read** the task + its acceptance criteria + relevant PRD section.
2. **Inspect** current code (`src/lib/nav.tsx`, `store.ts`, `auth.tsx` first — they're the spine).
3. **Plan** the smallest change set; list touched files.
4. **Implement** following existing patterns (Tailwind utility styling, `ModulePlaceholder` → real page, role checks via `NAV` config).
5. **Verify**: `npm run build`, then `npm run dev` smoke-check the changed route.
6. **Report**: what changed, criteria pass/fail, anything blocked, next task.
7. **Commit** only after user-approved pushes; conventional messages (`feat:`, `fix:`, `docs:`, `refactor:`).

**Report template:**
```
Task: T2.2
Done: yes/no
Verified: build ✅ | route smoke ✅
Files: <list>
Blocked: <none | decision ID / missing input>
Next: T2.3
```
