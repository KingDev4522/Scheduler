## 3. The judge workflow (the backend question)

The starter README states: *“Judges will reset your app, generate the timetable themselves and apply
change files of their own.”*

That workflow requires the **deployed app** to:

1. reset to a clean state,
2. import `cit_public.json` (or accept the bundled one),
3. run the solver,
4. validate and display the result,
5. accept an arbitrary disruption/change file,
6. produce `schedule_after.json` and the diff,
7. download the exports.

**Answer: yes, a backend is required.** The frontend alone cannot run OR-Tools CP-SAT. The current
Python engine is an offline CLI: it proves the algorithm and produces valid exports, but it is not
callable by the browser. Under D1 = A the site is a demo; it cannot satisfy the judge workflow.

**Recommended architecture (D1 = B/C):**

```
React SPA ──HTTP──▶ FastAPI
                    ├─ POST /api/import        (validate cit_public.json)
                    ├─ POST /api/generate      (CP-SAT weekly + exams; job id)
                    ├─ GET  /api/jobs/{id}     (status/progress/result)
                    ├─ POST /api/validate      (run validator.py unmodified)
                    ├─ GET  /api/schedule      (sessions, exams, bookings)
                    ├─ POST /api/disruption    (proposal + diff, no auto-apply)
                    ├─ POST /api/approve       (Admin only, requester != approver)
                    ├─ GET  /api/exports/*     (schedule.json / schedule_after.json)
                    └─ POST /api/reset         (Admin demo reset)
```

The SPA then needs official-data screens for Admin (generate/validate/export), Bookings, Changes,
Approvals, Exams and Timetables. That is Phase 4/5 work.

## 4. Compliance actions, highest value first

1. **Backend service** wrapping the existing `solver/` (FastAPI, job status, timeouts, validator run,
   exports, reset). Without it the judged workflow is impossible.
2. **Wire the official dataset/artifacts into the UI** (Timetables, Exams, Bookings, Changes,
   Approvals, Admin). Screens currently show demo data.
3. **Manual booking form** that works with AI disabled and validates hard constraints.
4. **Deploy** (frontend + backend + persistent storage) and verify in incognito.
5. **README architecture diagram + engine setup** and commit `exports/*`.
6. **Record the ≤5-minute video** after deployment.
7. **Freeze** commits/deployment before the deadline; verify repo creation date, four accounts,
   admin reset, AI/third-party declarations, and no secrets.
